# Task

We're running the MVP strategy pipeline for grostak-v2 and need to understand how injection site tracking is stored and synced to the platform.

Jake's original product doc lists injection site tracking (site location, soreness, time of day) as a core patient feature. It's not visible in any grostak-v2 API route or data model — our hypothesis is that it either lives in the mobile app only, or is embedded in a JSON payload on an existing endpoint (e.g. inside the Dose model's notes field, or a check-in payload).

**Question:** How does stak-app store injection site data locally, and how (if at all) is it communicated to the grostak-v2 API? Specifically:

1. Is there a dedicated injection site model/table in the local SQLite DB, or is it stored as part of a dose log or check-in?
2. Is it synced to grostak-v2? If so, which endpoint receives it and in what shape?
3. If it's not synced yet — is it planned, or is it mobile-local only for now?

This will determine whether injection site tracking needs a new use case + API spec in grostak-v2, or whether it's already flowing through an existing endpoint we missed.

# Completion Notes

Please describe the local data shape and sync status. A one-paragraph answer is fine.

# Response from stak-app:main

Injection site data is **not stored in the local SQLite DB and not synced to grostak-v2**. Here's the full picture:

1. **No dedicated table.** The local `doses` table (lib/db.ts:117) has columns: `id`, `protocol_id`, `logged_at`, `time_slot`, `mood_rating`, `energy_rating`, `notes`, `created_at`, `synced_at` — no `injection_site` column.

2. **Not synced.** The `logDose` call in `hooks/useDoses.ts:87` sends `protocolId`, `loggedAt`, `timeSlot`, `moodRating`, `energyRating`, `notes` to `POST /patients/me/doses` — `injection_site` is not in the payload. The `LogDoseOptions` type (useDoses.ts:25) declares `injection_site?: string | null` as an option, but `logDose` never reads or forwards it.

3. **Mobile-local only — partially.** `injection_site` appears in `lib/protocol-stats.ts:57` and `lib/stak-score.ts:133` where it's used to compute rotation score (distinct injection sites in recent doses). These functions read from the local SQLite result set — but since the column doesn't exist in the DB schema, it always resolves to `undefined`. This is the spec-v18 bug: the rotation score component of the Stak Score is effectively broken/zeroed because injection site data is never persisted anywhere.

**Conclusion:** grostak-v2 needs a new `injection_site` field on the Dose model and on `POST /patients/me/doses`. stak-app needs a corresponding DB column, sync path, and logDose wire-up. This is tracked as spec-v18 (Injection Site Field Drop / Rotation Score regression) — currently Draft, unstarted.
