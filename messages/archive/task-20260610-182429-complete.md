# Task Description

grostak-v2 just shipped v29 (patient account management) and v30 (notifications
infrastructure). These are endpoints stak-app has been blocked on — they're live
now. Before you wire them up, we need you to write specs for your patient auth
and push notification flows so we can align contracts and close the remaining
E2E test gaps together.

## What shipped on grostak-v2

**v29 — Patient Account Management** (`PATCH/DELETE /patients/me/...`, all require patient JWT):

- `PATCH /patients/me/email` — `{ email: string }`. Returns 200 on success, 409
  duplicate, 422 bad format, 422 `email_change_not_supported_for_oauth` for
  OAuth-only accounts (no Clerk password). Calls Clerk Backend API server-side.
- `PATCH /patients/me/password` — `{ currentPassword, newPassword }`. Verifies
  current password via Clerk before updating. Returns 422 `invalid_current_password`,
  422 `password_too_weak`, 422 `password_change_not_supported_for_oauth` for
  OAuth accounts.
- `DELETE /patients/me/account` — soft-deletes Patient row, schedules Clerk
  account deletion, returns 204. Subsequent requests with same JWT return 401.
- `POST /patients/me/data-export` — async, returns 202 immediately. Rate-limited
  to 1 request per 30 days (429 if exceeded). Delivery via email within 72h
  (email provider with BAA is a pre-launch gate — not live yet).

**v30 — Notifications Infrastructure**:

- `POST /patients/me/push-token` — `{ token: string, platform: "ios"|"android" }`.
  Registers an Expo push token. Upserts (duplicate = 201, not error). Returns 400
  on invalid platform.
- `DELETE /patients/me/push-token` — removes all tokens for the calling patient.
  Returns 204.
- `PATCH /patients/me/protocols/:id` now accepts `reminderTime` (HH:MM) and
  `reminderEnabled` (boolean). `reminderEnabled: false` suppresses delivery
  without clearing the stored time.
- `GET /patients/me/notifications` — returns last 50 `NotificationLog` entries
  for the patient (`{ id, type, title, body, status, createdAt }`).

The reminder scheduler runs server-side every 5 minutes, matches protocols within
±5 min of `reminderTime` (UTC for MVP — timezone field is post-MVP), and delivers
via Expo Push. Delivery results written to `NotificationLog` with
`status: sent | failed | token_removed`.

# Completion Notes

## What was done

**spec-v19: Patient Auth Flow (Clerk + grostak-v2)** — `specs/spec-v19-patient-auth-flow.md`

- Documents the full Clerk auth contract: email/password path (`clerkSignIn.create` + `setActive`), Google OAuth path (`useOAuth { strategy: 'oauth_google' }` + `startGoogleOAuth`), and Apple OAuth path (`useOAuth { strategy: 'oauth_apple' }` + `startAppleOAuth`). All three paths produce an identical `session.getToken()` → Clerk JWT, injected as `Authorization: Bearer` in `api-client.ts`.
- Specifies `isEmailPasswordAccount(user)` utility using `clerkUser.passwordEnabled` (the Clerk-idiomatic signal). OAuth-only users have `passwordEnabled: false`; these users will never see Change Email or Change Password in the UI and those endpoints will not be called for them.
- Specifies `setup-test-env.sh` (in `.claude/scripts/`) that provisions both test users via Clerk Management API: email/password user via standard `POST /users`, OAuth-only user via `POST /users` with `skip_password_requirement: true`. Credentials written to gitignored `.env.test.external` (`TEST_USER_EMAIL`, `TEST_USER_PASSWORD`, `TEST_OAUTH_USER_CLERK_ID`).

**spec-v20: Push Token Registration (grostak-v2 v30)** — `specs/spec-v20-push-token-registration.md`

- Specifies replacing the TODO stub in `lib/notifications.ts` with a real `POST /patients/me/push-token { token, platform: 'ios' }` call on permission grant.
- Specifies pending-token retry: failure stores to AsyncStorage `stak:push_token_pending`; `flushPendingPushToken` runs inside `syncAll` on every foreground/sign-in.
- Specifies `DELETE /patients/me/push-token` on sign-out (non-fatal — must not block offline sign-out).
- Extends `UpdateProtocolRequest` type with optional `reminderTime?: string` and `reminderEnabled?: boolean`.
- Specifies `useNotificationLog` hook for `GET /patients/me/notifications` (live fetch, no SQLite cache for MVP).
- Specifies `__DEV__`-gated token log in `registerForPushNotifications` so the Expo push token surfaces in Metro console. `.env.test.external` extended with `TEST_EXPO_PUSH_TOKEN`.
