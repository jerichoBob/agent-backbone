# CR: spec-v18 — Add injection_site to Dose model and API

## Summary

The `injection_site` field has never existed in grostak-v2. It was present in the old Supabase schema but was never ported. As a result, the Rotation pillar of the Stak Score is permanently dead for all injectable users — the most important subset of the target audience.

This CR covers **Phase 1 of spec-v18 only** — the grostak-v2 server-side work. stak-app will handle Phases 2–7 (SQLite migration, API client, write path, sync path) once this lands on the platform side.

## What grostak-v2 needs to do

### 1. Prisma schema

Add to the `Dose` model in `prisma/schema.prisma`:

```prisma
injectionSite   String?
```

Migration name: `add_dose_injection_site`

### 2. Route handler — write

Update the create-dose Zod schema to accept:

```ts
injectionSite: z.string().nullish()
```

Use the same strict-vs-permissive posture already chosen in spec-v17 (Phase 3). Do not introduce a third pattern.

### 3. Route handler — read

Update the list-doses and get-dose response serializers to include `injectionSite` in every dose response payload. Field should be `string | null`.

### 4. Integration test (AC-10 from spec-v18)

Add an integration test that:

- POSTs a dose with `injectionSite: "left_thigh"`
- GETs the dose back
- Asserts `injectionSite === "left_thigh"`

## Acceptance criteria (platform side)

- `POST /patients/me/doses` accepts `injectionSite: string | null`
- `GET /patients/me/doses` returns `injectionSite` on every dose object
- Integration test passes in CI
- No change to existing dose fields (mood, energy, timeSlot, notes) — regression safe

## Full spec for context

The complete spec-v18 is at `stak-app/specs/spec-v18-injection-site-field-drop.md`. It includes the full problem statement, all five drop sites, user stories, acceptance criteria, and the downstream reads that will automatically come back to life once the vertical is restored.
