# Problem Statement

`createProtocol` on the grostak-v2 patient API silently drops every optional field when saving a new protocol. The mobile client sends a fully populated camelCase payload (per the OpenAPI contract) and gets a 200 OK back, but the persisted record contains only `name`, `type`, and `category` — everything else is null.

Confirmed: the mobile payload is correct end-to-end. A console log immediately before the `fetch` call shows all fields populated. The drop happens server-side.

**Suspected root cause:** the Prisma `create` call is missing the optional fields from its `data` object, likely a validation/transform step that only passes through required fields. A secondary suspect is that `THREE_X_WEEK` and non-empty `scheduleDays` are the differentiating values — every working save in the dataset uses `WEEKLY`, `TWICE_WEEKLY`, `CUSTOM`, or `DAILY` and omits `scheduleDays` entirely.

**Concrete example — what was sent vs. what was persisted:**

```jsonc
// Wire payload (verified)
{
  "name": "Enclomiphene",
  "type": "MEDICATION",
  "doseAmount": "12.5",
  "doseUnit": "MG",
  "scheduleType": "THREE_X_WEEK",
  "scheduleDays": ["mon", "wed", "fri"],
  "scheduleTimes": ["morning"],
  "pillCount": 20
}

// Returned by API / saved in Postgres
{
  "id": "32090b46-b8bb-4399-a9eb-aa901c996fa7",
  "name": "Enclomiphene",
  "type": "MEDICATION",
  "category": "medication",
  "doseAmount": null,
  "doseUnit": null,
  "scheduleType": null,
  "scheduleTimes": [],
  "pillCount": null
}
```

Full spec with differential analysis and acceptance criteria: `stak-app/specs/spec-v17-grostak-v2-protocol-write-field-drop.md`

# Solution Recommendation

1. Find the `createProtocol` handler (likely `patients/me/protocols` POST route in grostak-v2)
2. Audit the Prisma `data` object — confirm all optional fields (`doseAmount`, `doseUnit`, `scheduleType`, `scheduleDays`, `scheduleTimes`, `pillCount`, `concentrationMgPerMl`, `vialVolumeMl`) are passed through
3. Check for any Zod/validation transform that might be stripping unknown or optional keys before the Prisma call
4. Verify `THREE_X_WEEK` is a valid enum value in the Prisma schema
5. Verify `scheduleDays` is a mapped column (not omitted from the schema)
6. Fix, then write an integration test: POST a full payload including `THREE_X_WEEK` + `scheduleDays`, assert all fields round-trip

# Implementation Notes

**Root cause confirmed:** `POST /patients/me/protocols` handler (`apps/api/src/routes/patients/me/protocols.ts`) had a TypeScript body type that only declared `name`, `type`, and `notes`. All other fields were invisible to the handler and absent from the Prisma `create` call.

**What was fixed:**

- `apps/api/src/routes/patients/me/protocols.ts` — POST handler body type expanded to include all optional fields; Prisma `data` object now passes them all through
- `docs/api/openapi.yaml` — `POST /patients/me/protocols` request schema updated to document all accepted fields

**Schema/contract notes:**

- `doseAmount`, `concentrationMgPerMl`, `vialVolumeMl` — accepted as decimal strings (matching Prisma `Decimal` type)
- `doseUnit` — maps to `DoseUnit` enum (`MG`, `MCG`, `ML`, `IU`, `G`, `TABLET`, `CAPSULE`, `DROP`, `SPRAY`, `PATCH`, `PERCENT`)
- `scheduleType` — maps to `ScheduleType` enum; `THREE_X_WEEK` is valid ✓
- `scheduleDays` — `String[]` in schema ✓; passes through directly
- `scheduleTimes` (array) — **no direct column match**. Schema has `scheduleTime String?` (singular). Fix: `scheduleTimes[0]` is stored as `scheduleTime`. stak-app should be aware of this lossy mapping — only the first element is persisted.
- `pillCount` — **no dedicated column** in `Protocol`. Stored in `config.pillCount` (the `Json` extension bag per ADR-009). stak-app must read it back from `protocol.config.pillCount`, not a top-level field.
- `scheduleTime` is returned top-level in the response; `config` JSON includes `pillCount` when set.

**Breaking changes:** None — additive only. All previously sent payloads (name+type+notes) continue to work identically.

**Test added:** `tests/integration/patient-fixture.ts` — new section "Phase 2 — POST /patients/me/protocols: all optional fields round-trip (regression: field-drop bug)". Posts full payload with `THREE_X_WEEK` + `scheduleDays` + `pillCount`, asserts all 6 fields round-trip. 135/135 passing.

**Known gaps / deferred:**

- `scheduleTimes` array → single `scheduleTime` string is lossy. If stak-app needs multi-time-of-day support, a schema change (`scheduleTime String[]`) is needed — not done here.
- `pillCount` lives in `config` JSON, not a typed column. A future migration could promote it to `pill_count Int?` on the `Protocol` table for query-ability.
