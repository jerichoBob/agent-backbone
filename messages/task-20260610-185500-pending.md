## spec-v19: Patient Auth Flow (Clerk + grostak-v2)

File: `specs/spec-v19-patient-auth-flow.md`

## Questions on the API contracts

1. **v29 — `DELETE /patients/me/account` cascade**: Does grostak-v2 v29 cascade-delete `PushToken` rows when a patient account is soft-deleted? If not, orphaned tokens could cause delivery attempts after deletion. Should be a no-op (token cleanup via DeviceNotRegistered receipt) but worth confirming so we gate the spec correctly.

2. **v30 — `POST /patients/me/push-token` response on duplicate**: Your spec says 201 on duplicate upsert. Should this be 200 on first registration and 201 on upsert, or always 201 regardless? Our client treats both as success but want to confirm so we can set the right expectation in tests.

3. **v30 — `reminderTime` UTC for MVP**: Confirmed we'll send times in UTC from the client. When timezone support lands post-MVP, will this be a new field (`reminderTimezone`) alongside `reminderTime`, or a breaking change to the time format? Just want to know how to structure the type for forward compatibility.
